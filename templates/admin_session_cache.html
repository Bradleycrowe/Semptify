🔐 Session Management - Administrator Control

3-Layer Session Cache System

Current Status: ENABLED (default)

📋 How to Toggle

  1. To ENABLE caching (recommended for production): 
    $env:USE_SESSION_CACHE = "True"
    .\.venv\Scripts\python.exe Semptify.py
  2. To DISABLE caching (troubleshooting only): 
    $env:USE_SESSION_CACHE = "False"
    .\.venv\Scripts\python.exe Semptify.py
  3. Or add to .env file: 
    USE_SESSION_CACHE=True

⚙️ System Configuration

Setting Value Description
SESSION_TIMEOUT 14400 sec (4 hours) How long before session expires
SLIDING_WINDOW 1800 sec (30 min) Activity extends session
CACHE_TIMEOUT 3600 sec (1 hour) Storage client cache duration
AUTO_RENEW True Auto-reload from storage if session expires

🔒 Security & Compliance

  • ✅ NIST 800-63B compliant: 4-hour session timeout meets guidelines
  • ✅ OWASP best practices: HttpOnly cookies, SameSite protection
  • ✅ Sliding window: Prevents mid-activity logouts
  • ✅ Auto-renewal: Seamless user experience without compromising security
⚠️ Production Deployment:
Set SESSION_COOKIE_SECURE = True in Semptify.py when using HTTPS.
Currently set to False for localhost HTTP development.

🎯 When to Disable Caching

  • Troubleshooting session-related issues
  • Testing with frequent token changes
  • Low-memory environments (unlikely with 5KB per user)
  • Debugging storage connectivity problems

📝 Architecture Overview

Layer 1: Long-term identity in user's Dropbox (/auth_token.enc)

Layer 2: Active session in Flask cookie (4-hour expiry, sliding window)

Layer 3: Storage client cache in memory (1-hour TTL, ~100x faster)
