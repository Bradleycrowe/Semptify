🛣️ Highway-Inspired Architecture

Layered routing system with detours, alternate routes, and express lanes

🛣️ SOLUTION 1: INTERSTATE HIGHWAY SYSTEM

Concept: Main express routes with clear exits, rest stops, and alternative paths. Each role gets dedicated lanes.

Layer 1: Express Lane (Admin/Legal) - No Speed Limits

Who: Admin, Legal professionals

Route: Direct system access, bypass all checkpoints

/ → Check session['express_pass'] → Direct to dashboard No OAuth detours No storage selection stops Token = Express Pass (validated once at entrance)
  • Admin token in security/admin_tokens.json = Express Pass
  • Legal token with professional credentials = Express Pass
  • Skip all middleware checkpoints except rate limiting
  • Own dedicated storage (not shared with regular traffic)

Layer 2: Main Highway (User/Manager) - Standard Routes

Who: Regular users, Organization managers

Route: OAuth toll booth, storage rest stop, then destination

/ → Role selection (choose your route) → OAuth toll booth → Storage rest stop → Dashboard destination
  • Must stop at toll booth (OAuth)
  • Must stop at rest area (storage selection)
  • Token = Toll receipt (proves you paid)
  • Can take detours (library, help) without re-authentication

Layer 3: Local Roads (Advocate/Guest) - Limited Access

Who: Advocates, counselors, temporary users

Route: No toll, limited destinations, temporary pass

/ → Role selection → Temporary pass issued → Limited destinations (library, resources only)
  • No OAuth required (local roads)
  • Temporary session (expires quickly)
  • Can only access public resources
  • No vault, no personal storage
✅ PROS:
  • Clear separation of traffic (roles don't interfere)
  • Admin/Legal get fastest path (no OAuth delays)
  • Users get guided journey (clear steps)
  • Advocates get immediate access (no setup)
  • Easy to understand (everyone knows highways)
❌ CONS:
  • Still requires role selection first (one entry point)
  • Express pass holders might abuse if not validated
  • Multiple code paths to maintain (3 authentication systems)

🧭 SOLUTION 2: SMART GPS ROUTING (Token-Based Detection)

Concept: System detects where you're trying to go and automatically routes you. No role selection needed upfront.

Layer 1: Destination Detection

How it works: User enters any URL, system detects needed permissions

User visits: /admin → System detects: requires admin role → Check session for admin token → Not found? Check for ANY token (user, legal, etc.) → No token? Offer appropriate auth path
  • No forced role selection
  • System figures out what you need based on destination
  • Token format tells system your role: ADMIN-xxx, USER-xxx, etc.
  • If you have wrong role, suggest correct entry path

Layer 2: Smart Detours

Example flows:

SCENARIO A: User visits /library (public) → No auth needed → Show content immediately → If they try to save something: NOW prompt for auth SCENARIO B: User visits /vault (private) → Needs token → Check URL: ?user_token=xxx present? → Yes: Use that token, validate, continue → No: Detect no token, offer OAuth SCENARIO C: Admin visits /admin → Needs admin token → Check session['admin_token'] → Not found: Show admin login (not OAuth) → Found: Validate and continue

Layer 3: Token Auto-Routing

Token format determines path:

Token Format Detected Role Auto Route To Storage

USER-xxxxxxxxxxxx User /gui OAuth
LEGAL-xxxxxxxxxx Legal /legal/dashboard OAuth + audit
MGR-xxxxxxxxxxxxx Manager /manager Org storage
ADV-xxxxxxxxxxxxx Advocate /resources Temp only
No prefix (old format) Legacy User Prompt to upgrade Migrate
✅ PROS:
  • No forced role selection! System figures it out
  • Existing users (your 784410067859 token) auto-detected as USER-
  • Bookmark URLs work (token in URL tells role)
  • Guest access works (no token = public routes only)
  • Natural user experience (go where you want, system guides)
  • Solves migration problem (old tokens auto-prefixed)
❌ CONS:
  • More complex middleware (must detect intent)
  • Edge cases: What if user has both admin AND user token?
  • Token format must be strictly enforced
  • Harder to debug (routing is implicit, not explicit)

🔄 SOLUTION 3: EUROPEAN ROUNDABOUT (Central Hub)

Concept: All traffic goes through central hub, which directs to appropriate spoke based on credentials.

Layer 1: Central Roundabout (Authentication Hub)

Single entry point: /auth

ALL requests → /auth hub ↓ Hub checks: Do you have ANY credential? ├─ Admin token? → Express exit to /admin ├─ OAuth token? → Highway exit to /gui ├─ Advocate badge? → Local road to /resources └─ Nothing? → Park at /welcome (choose your vehicle)
  • One middleware handles everything
  • Hub examines all possible credentials at once
  • Redirects to appropriate spoke
  • No role selection needed (hub decides)

Layer 2: Credential Hierarchy

If multiple credentials exist, priority order:

  1. Admin token (highest priority)
  2. Legal professional token
  3. Manager token
  4. User OAuth token
  5. Advocate temporary pass
  6. No credential (public access)

This solves the "multiple tokens" problem - admin always wins

Layer 3: Spoke Routes (Destinations)

┌─────────────┐ │ /admin │ (Admin spoke) └─────────────┘ ↑ ┌──────────────────┼──────────────────┐ │ │ │ ┌───────────┐ ┌──────────────┐ ┌───────────┐ │ /legal │←─────┤ /auth HUB │───→│ /gui │ │ (Legal) │ │ (roundabout) │ │ (User) │ └───────────┘ └──────────────┘ └───────────┘ ↓ ┌─────────────┐ │ /resources │ (Advocate spoke) └─────────────┘

Each spoke is completely independent - different UI, different features, different storage

✅ PROS:
  • Simplest architecture - one hub handles all routing
  • Solves multi-token problem (hierarchy)
  • Easy to add new roles (just add spoke)
  • Clear separation (each spoke is isolated app)
  • No role selection needed (hub detects credentials)
  • Works with existing tokens (hub auto-detects format)
  • Easy to understand codebase (one router, many handlers)
❌ CONS:
  • Every request goes through hub (potential bottleneck)
  • Hub must check ALL credential types (more work per request)
  • If hub breaks, entire system down
  • Caching becomes critical (can't check credentials every time)
